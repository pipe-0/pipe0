## Crustdata in thirty seconds

- What it is, with its own numbers labeled as claims: a B2B data API
  positioned on freshness, claiming 1B+ person profiles and 60M+
  companies in a live-searchable index, with signals (hiring,
  funding, headcount, posts) "timestamped within minutes to hours"
  rather than served from quarterly snapshots. YC Fall 2024, $6M
  seed, revenue reportedly $770K to $4M+ in seven months, and
  customers that matter for credibility: Y Combinator itself and
  agent.ai.
- Why agents specifically care, two sentences: an agent deciding
  whether to reach out today needs current title and company, not
  last quarter's. Real-time lookup APIs exist for the moment of use,
  and agent workflows are all moment of use; Garry Tan's "gateway to
  the internet for agentic apps" line is the thesis in one quote.

## Yes, there is an official MCP server

- Lead with the correction because directories get it wrong:
  Merge.dev's connector page states Crustdata offers no official MCP
  server; Crustdata's own domain says otherwise. The official server
  lives at mcp.crustdata.com (streamable-http endpoint /mcp), with
  one-click OAuth setup for Claude, Claude Code (claude mcp add),
  Cursor, and VS Code, and API-key setup for other clients; keys
  come from app.crustdata.com/api-keys. Their GitHub org also ships
  MIT-licensed Claude skills (crustdata/skills) built on the same
  APIs.
- The trap this illustrates, one sentence: MCP directories and
  connector marketplaces lag vendors by months in both directions,
  listing dead servers and missing live ones; verify on the
  vendor's domain.

## What shapes the direct path

- The mechanics a builder needs before choosing: enrichment calls
  cap at 25 records per request, with async batch jobs up to 10,000
  records returning gzipped JSONL via links valid five days; rate
  limits run 15/min on enrich, 30/min on search, 10/min on live web
  endpoints; company enrichment costs 2 credits (plus 2 for
  technographics); autocomplete and web search are free.
- The two gates to know about: there is no public dollar pricing
  (credit tiers are contact-sales), and the live web endpoints are
  enterprise-plan-only. Neither is disqualifying; both belong in
  the estimate before you commit an agent workflow to the direct
  path.
- When direct is right, stated fairly: Crustdata-only workloads, an
  existing contract, or endpoints a meta provider does not surface
  (posts, watcher, live web).

## Path two: Crustdata inside pipe0

- The factual pitch: pipe0 already exposes Crustdata as pipes and
  searches (people:profiles:crustdata, company:identity:crustdata,
  person:posts:content:crustdata), so one auth and one MCP server
  put Crustdata in the same toolset as work-email waterfalls,
  ZeroBounce validation, and CRM writes.
- The composability argument is the substance: a Crustdata profile
  search feeding a waterfall, then validation, then a Salesforce
  update is one agent conversation on one server, versus four
  integrations on the direct path. And billing is per successful
  result with published credit costs, versus contact-sales pricing.
- Keep the exclusivity wording exact: pipe0 carries premium
  providers like Crustdata and Amplemarket, and is the only meta
  provider allowed to offer Amplemarket data.

## The legal ground, factually

- Readers evaluating LinkedIn-derived data deserve the map, stated
  without editorializing: the Ninth Circuit held (hiQ v. LinkedIn,
  reaffirmed 2022) that scraping public data does not violate the
  CFAA, but hiQ itself ended in a $500,000 consent judgment on
  contract and tort claims. LinkedIn sued Proxycurl in January 2025
  over alleged fake-account scraping; Proxycurl shut down that July
  at roughly $10M ARR. The live risk in this category is contract
  and fraud theories, not anti-hacking law.
- What a buyer does with that, one practical line: ask any
  LinkedIn-adjacent vendor how it sources (public-only collection
  and compliance posture are the questions that mattered in both
  cases), and prefer vendors who answer in writing. Crustdata
  positions itself openly for displaced Proxycurl customers; the
  diligence question is the same for every vendor in the category.

## A worked example, then the boundary

- Script the demo end to end: ask Claude Code to find profiles
  matching an ICP via the Crustdata search, pull recent posts for
  the top matches, waterfall work emails, validate, push qualified
  rows to the CRM. Short annotated transcript: the prompt, the
  tools chosen, statuses on the cells.
- Close on the boundary line, one sentence each: go direct when
  Crustdata is the whole stack; go through the meta provider when
  Crustdata is one ingredient in a pipeline. Nothing after that.
