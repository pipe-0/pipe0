## Why agents and waterfalls compose

- One paragraph per concept, linking the existing deep dives: a
  waterfall tries providers in order until one returns a verified
  result; MCP is how agents discover and call tools, including paid
  data tools. The thesis: agents are good at judgment (who to
  enrich, what a miss means) and bad at being data providers;
  waterfalls are the opposite. Wire them together and the agent
  stops hallucinating contact data and starts orchestrating
  verified lookups.

## Which MCP servers support waterfall enrichment logic?

  single provider, so a miss is a dead end; only a handful cascade
  across providers server-side, and as of August 2026 the verified
  list is Clay, pipe0, Cleanlist, SyncGTM, and FullEnrich.

## An annotated run

- A transcript-shaped example: "find work emails for these eight

  waterfall pipe, cells resolving with statuses, and no_result as

- The cost-control section, addressing the real anxiety with the
  real facts: no MCP server on the market implements a hard
  confirm-before-spend prompt in the protocol today, so spend
  control is structural, and the structures that exist are:
  pay-on-success billing (a miss across the whole cascade costs
  nothing), inline validation that refuses a malformed run before
  it spends anything (there is no separate dry-run tool; the run
  is the check), scoped API keys, and the fact that a run only
  fills unresolved cells so re-runs never double-charge. State what
  pipe0 implements of these plainly; mention Firecrawl's
