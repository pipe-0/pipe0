The pipe0 MCP server lets you search and enrich data directly from any MCP-compatible client. This includes
Claude, ChatGPT, Claude Code, Cursor, and custom agents.

The server exposes pipe0's <AppLink linkType="pipeCatalog">enrichment</AppLink> and <AppLink linkType="searchCatalog">search</AppLink> capabilities as MCP tools.

```txt title="MCP server URL"
https://api.pipe0.com/v1/mcp
```

## Authentication

The MCP server authenticates with OAuth. When you connect, your client opens a browser window where you
sign in to pipe0 and approve access. You never enter a client ID or client secret. The server registers
clients automatically through dynamic client registration.

<Callout>
  API keys do not work for the MCP server. They keep working for the REST API. If your client
  configuration sends an `Authorization` header with an API key, remove the header and reconnect
  with OAuth. If your client cannot sign in with OAuth at all, use an [MCP token](#clients-without-oauth).
</Callout>

## Claude and Cowork

Connectors added on claude.ai are available in the Claude web app, the desktop app, and Cowork.

<Steps>
<Step>
Open **Settings > Connectors** and click **Add custom connector**.
</Step>
<Step>
Enter a name, for example `pipe0`, and set the remote MCP server URL to `https://api.pipe0.com/v1/mcp`.
Leave the OAuth client ID and secret under **Advanced settings** empty.
</Step>
<Step>
Click **Add**, then **Connect**. Sign in to pipe0 in the browser window and approve access.
</Step>
</Steps>

## Claude Code

Add the server from your terminal:

```bash title="Add the pipe0 MCP server"
claude mcp add --transport http pipe0 https://api.pipe0.com/v1/mcp
```

Run `/mcp` inside Claude Code, select **pipe0**, and choose **Authenticate**. Claude Code opens the
browser for the OAuth flow and stores the token.

## Cursor

Add the server to `~/.cursor/mcp.json`, or to `.cursor/mcp.json` inside a project:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "pipe0": {
      "url": "https://api.pipe0.com/v1/mcp"
    }
  }
}
```

Open **Settings > MCP**. Cursor shows a login prompt next to `pipe0`. Click it to sign in and approve
access.

## ChatGPT

<Steps>
<Step>
Open **Settings > Plugins**, select the **MCPs** tab, and choose **Connect to a custom MCP**.
</Step>
<Step>
Enter a name, for example `pipe0`. Set the type to **Streamable HTTP** and the URL to
`https://api.pipe0.com/v1/mcp`. Leave the bearer token and header fields empty.
</Step>
<Step>
Click **Save**, then sign in to pipe0 in the browser window and approve access.
</Step>
</Steps>

## Other MCP clients

Any client that supports the streamable HTTP transport and OAuth can connect with this configuration:

```json title="MCP configuration"
{
  "mcpServers": {
    "pipe0": {
      "url": "https://api.pipe0.com/v1/mcp"
    }
  }
}
```

The client discovers the OAuth endpoints from the server and starts the sign-in flow on first use.

## Clients without OAuth

Use OAuth whenever your client supports it. If it cannot sign in with OAuth, connect with an MCP token
instead: a token you create in pipe0 and your client sends in the `Authorization` header.

<Steps>
<Step>
Open **API and MCP** in the sidebar. Under the MCP server URL, click **Create a token**.
</Step>
<Step>
Name the token, choose when it expires (up to five years), and copy it. It is shown only once.
</Step>
<Step>
Add the server to your client with the header `Authorization: Bearer <token>`.
</Step>
</Steps>

For example, in Cursor:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "pipe0": {
      "url": "https://api.pipe0.com/v1/mcp",
      "headers": {
        "Authorization": "Bearer ${env:PIPE0_MCP_TOKEN}"
      }
    }
  }
}
```

Cursor reads the token from the `PIPE0_MCP_TOKEN` environment variable, so it stays out of the file.

In Claude Code:

```bash title="Add the pipe0 MCP server with a token"
claude mcp add --transport http pipe0 https://api.pipe0.com/v1/mcp \
  --header "Authorization: Bearer <token>"
```

A client that only runs local (stdio) servers can connect through [`mcp-remote`](https://www.npmjs.com/package/mcp-remote):

```json title="MCP configuration"
{
  "mcpServers": {
    "pipe0": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://api.pipe0.com/v1/mcp", "--header", "Authorization:${PIPE0_AUTH}"],
      "env": { "PIPE0_AUTH": "Bearer <token>" }
    }
  }
}
```

An MCP token acts as you, like an OAuth connection. Treat it like a password: anyone who holds it can
use pipe0 as you. It appears under **Account > Connected apps**, where you can revoke it at any time.
When it expires or is revoked, the client gets `401 Unauthorized` and needs a new token.

## Available tools

The server exposes the full pipe0 surface, grouped by what an agent does with it:

- **Discover**: browse the catalogs and their schemas (`list_pipes`, `list_searches`, `list_effects`, `list_playbooks`, `get_pipe_schema`, `get_search_schema`, `get_effect_schema`, `get_playbook`, `get_guide`, `get_provider_context`, `autocomplete_field`).
- **Account resources**: list what your organization already has (`list_connections`, `list_secrets`, `list_sheets`, `list_buckets`, `list_schedules`).
- **Validate**: every run tool checks its payload before anything runs. An unknown key, a wrong shape, or a filter value the provider does not recognize comes back as a named error, and nothing is billed. `validate_effects` previews a sheet chain without committing it.
- **Run**: execute searches, enrichments, and effects, and track them (`run_pipes_oneshot`, `run_search_oneshot`, `run_effects`, `check_run_status`, `wait_for_run`, `cancel_effect_run`, `verify_outcome`).
- **Sheets**: create and read enrichment sheets (`create_sheet`, `get_sheet_schema`, `get_sheet_rows`, `get_field_values`, `get_recent_effects`). To see which pipes fit a result, call `list_pipes` with the `run_id`; each pipe comes back as runnable or with the fields it still needs. See [what agents do with sheets](/docs/sheets/ai-agents).
- **Reports**: create and read versioned report documents that sit next to your sheets (`create_report`, `read_report`). Report content is written through `run_effects`.
- **Schedules**: automate recurring runs (`create_schedule`, `update_schedule`, `delete_schedule`).

Tools that spend credits or mutate data ask for confirmation on the first call; the agent retries with `confirm: true` to proceed.

All MCP requests are <AppLink linkType="billing">billed</AppLink> like regular API requests.
